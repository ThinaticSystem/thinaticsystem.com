# 必要機能込みの性能予算 v1

この性能予算は、旧方式で取得したペア比較の計測結果に、必要な機能を含めた別のサイズ上限を適用する判定基準。
再測定するのではなく、既存の計測結果を読み、サイズ・リクエスト数・時間を分けて評価する。
現行の`perf:current`とは別の仕組みで、旧比較の失敗記録や公開の可否を置き換えない。

`test/functional-budget-v1.json`に、品地さんが承認した予算案v2の数値を固定している。
内容のhashは`scripts/functional-budget-evidence.mjs`で照合する。
旧`performance-check.mjs`、ペア比較の計測器、比較条件を固定するcontrol、失敗記録は書き換えない。

## 判定の実行

入力には、旧方式で新たに取得した、欠測のないペア比較の計測結果1回分を使う。
`perf:budget`自体は再測定を開始せず、測定値がよくなるまで再実行する用途には使わない。

```sh
corepack pnpm run test:budget-contract
corepack pnpm run perf:budget --paired-run .artifacts/paired-ci/run-EXACT \
  --paired-exit .artifacts/OWNED/paired-once.exit.json
```

固定Nix環境内で通常の`corepack pnpm run check`を実行すると、この判定器のテスト用データによる検証も走る。

### 計測結果と実行記録の照合

`paired-exit`には、`runOwnedCommand`の生の実行結果に次の情報を付けた、親プロセスの実行記録を渡す。

- `executable: corepack`
- `args: [pnpm, run, perf:paired]`
- 実際の作業ディレクトリ（cwd）

同じ接頭辞の`.supervision.json`と`.stdout.log`も必須。
標準出力にある計測ディレクトリ、8観測、終了結果、ソースとビルドの識別情報を照合する。
結果は毎回新しい`.artifacts/functional-budget/run-*/result.json`に保存し、旧PASSの再利用や上書きはしない。

## 適用する上限と比較規則

| 判定対象 | 承認済みの上限・規則 |
| --- | --- |
| 初期JS/CSS | raw 458,752 B / gzip 131,072 B / Brotli 114,688 Bをすべて同時に満たす |
| 固定操作での追加JS/CSSのデコード後のサイズ | blog list 20,480 B、article 7,168 B、discography list 5,120 B |
| 作品詳細コンポーネントのチャンク単体 | 16,384 B。画面全体の上限ではない |
| 全出力JS/CSS | 819,200 B。内容が重複してもファイルごとに数える |
| その他の操作・全リクエスト数・リソースのエントリー数 | 承認時上限と新たに測定したbaselineの上限の両方を維持する |
| 時間比較 | 固定ABBA/BAAB・両側4観測の中央値を使い、20%条件を変更しない |

サイズの上限は開発上の配分として丸めた値で、利用者の遅延SLOを実証した値ではない。
増分を認めない旧比較の結果は`historicalRaw`にそのまま残す。
旧失敗の種類は、加工前の完全な観測記録から再構成する。
未知の失敗、欠測、シグナル、タイムアウト、後片付けの成否不明を、診断情報だけに格下げしない。

### ファイルの移動や形式変更に対する確認

初期・各操作・全出力の制約は、それぞれ満たす必要があり、ある対象の削減で別の対象の超過を相殺しない。
作品詳細のチャンクはファイルのhash名ではなく、固定されたAngular component selectorから一意に特定する。
欠落、重複、初期読み込みへの移動を拒否する。

indexをスクリプトが実行されないDOMとして読み、既存の収集処理が取得したリソース集合と照合する。
未許可のinline script、外部script、クエリ付きで分類から漏れたリソース、Wasm/MJS/CJS、symlinkは自動合格しない。

承認済みアプリとビルド入力は、個々のファイルを特定できる正確な記録として保持する。
現版では、アプリ入力が変わると、アプリの構成と計測対象の範囲の再レビューを保守的に要求する。
将来の通常の修正でも該当することがあり、入力変更の自動承認やhashの自動更新は行わない。
これはhashで任意のコードの意味を証明する仕組みではなく、レビュー済みの構成の無断変更を防ぐ条件。
将来の更新では、数値枠の変更と、同じ数値枠に対する新しい構成・計測範囲のレビューを区別する。

## 結果の読み方

| 出力項目 | 判定する内容 |
| --- | --- |
| `size` | 承認した数値上限 |
| `requests` | リクエスト数とリソースのエントリー数 |
| `timing` | 変更していない時間規則 |
| `historicalRaw` | 旧比較の失敗を原文で保持 |
| `coverage` | 未測定範囲が残るため`BLOCKED` |
| `releaseAuthorization` | 常に`NOT_GRANTED` |

v1のCLI終了値は常に1。
サイズが合格しても、測定範囲が不足したまま全体を合格にはしない。
判定器のテスト成功とは意味が異なり、既存CIの旧paired/performanceコマンドも置換しない。

## 未測定の範囲と公開前の確認

画面全体の測定と上限承認が残る導線は、次の3つ。

- 新しく開いたページでの記事の初回表示
- 新しく開いたページでの作品詳細の初回表示
- 作品一覧から詳細への遷移全体

自サイトのJS/CSS、CMS・画像・フォント、外部プレーヤーのリソースを分離して実測し、
画面全体の上限を別途承認するまで未完了とする。
チャンク単体の16 KiBから画面全体の上限を推定・自動登録しない。

実サービスの再生、アカウント・Cookie・全画面表示、ホスティング実装、代表的なスクリーンリーダーなどの既存の確認も別途残る。
この変更では公開・commit・push・CMSへの書き込みを行わず、公開権限も与えない。
