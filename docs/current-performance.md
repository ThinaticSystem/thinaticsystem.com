# 性能比較テスト

旧版と変更後の版で、コンテンツを利用できるまでの時間と、読み込むファイルの量を比較するテスト  
CMSの応答をテスト用データに置き換え、同じブラウザーとデータで変更の影響を調べる

## 測定するもの

- **表示と操作にかかる時間**

  トップページ・記事・作品詳細の初回表示と、一覧から詳細への移動、一覧に戻る操作を測る  
  テーマ切替と、モバイルメニューの開閉も対象とする

- **操作中に読み込むファイル**

  JS/CSS、画像、CMS応答を分けて集計する  
  ファイルの展開後のサイズと、通信時のサイズも別々に記録する

- **ビルドで生成するファイル**

  初期JS/CSSと全出力JS/CSSのサイズを確認する  
  全出力には、測定中に開かなかったページのファイルも含む

表示時間は、本文を覆う要素がなくなり、コンテンツを利用できる状態になるまでを測る  
通常のアニメーションを有効にし、操作を妨げない装飾の終了は待たない

測定にはページ内の時計を使う  
DOMやスタイルの変化を捉える方式なので、画面への実際の描画時間やINPとは異なる

## 実行方法

Nixの開発環境またはCI環境で、次のコマンドを実行する  
旧版のビルドに使うNodeとCコンパイラーも、この環境に含まれる

```sh
corepack pnpm run perf:current
```

最初に変更後の版同士を4回測り、測定のばらつきを確認する  
続いて旧版をA、変更後の版をBとして、ABBA・BAABの順に計8回測定する

結果は`.artifacts/performance-v2/run-*/`へ保存する  
測定値に加え、実行結果とソース・ビルドの識別情報を確認できる

機能やアクセシビリティは、[ブラウザーテスト](quality.md)で別に検査する

## 結果の読み方

各版の中央値を比べ、時間は50msかつ20%、サイズは1,024Bかつ20%の増加をレビュー対象とする  
初期JS/CSSと全出力JS/CSSには、[性能判定の設定]で定めたサイズ上限も適用する

| 判定 | 意味 |
| --- | --- |
| `INCONCLUSIVE` | 同じ版同士の測定でばらつきが大きく、比較を判断できない |
| `REVIEW_REQUIRED` | 時間やサイズの増加がレビュー対象の基準に達した |
| `FAIL` | サイズ上限を超えた |
| `INVALID_EVIDENCE` | 必要な記録が欠けている、測定条件が一致しない、実行エラーがあるなど、測定が成立していない |
| `PASS_WITH_NOTES` | この比較テストの条件を満たした |

これはテスト環境での比較で、実利用時の応答時間の目標は別に定める必要がある  
結果の`absoluteUxAcceptance: NOT_ESTABLISHED`は、その目標に対する評価が未確定なことを示す

## 測定条件

HTTPキャッシュは無効にする  
新しく開いたページでの初回表示と、ページやモジュールを読み込み済みの状態での遷移を分けて測る

CMSのテスト用データは、実サービスの通信量や応答速度を再現するものではない  
モバイルの測定対象は現在メニュー開閉のみで、画面幅の指定も実端末のCPU性能を再現しない

### ファイルサイズの集計

初期JS/CSSは、ビルド後の`index.html`の`src`・`href`から直接参照されるファイルの合計  
JSが後から読み込むファイルは含まないため、初回表示で読み込む全ファイルのサイズとは異なる

静的ファイルは、両版を同じ圧縮器で処理して比べる  
画像・APIの絶対的な上限と、操作後も続く通信の集計範囲に対する予算は未確定

### 表示と通信の記録

テーマ切替は、保存値とボタンの状態に加え、背景色・文字色の変化を確認する  
判定には両版に共通するパレットを使うため、色設計を変更するときは計測側も合わせて見直す

通信はリクエスト開始時の操作に対応付けて記録する  
表示・操作の完了をドライバーが取得してから250msと、通信終了を待つ時間を含めて後続の通信を集計する

計測の実装は[`scripts/performance/`](../scripts/performance/)を参照

## 計測処理のテスト

計測処理を変更するときは、判定ロジックとブラウザー内の計測器をそれぞれ確認する

```sh
corepack pnpm run test:performance-contract
corepack pnpm run test:performance-recorder
```

メニューのアニメーションには専用の回帰テストも用意している  
ビルド後、出力先に未使用のディレクトリを指定して実行する

```sh
node scripts/performance/verify-menu-motion.mjs --dist dist/app/browser --output .artifacts/menu-motion
```

通常時の0.5秒と、動きを減らす設定での1msを確認し、開閉やBlogへの移動も検査する

旧方式の`perf:paired`と、その結果を読む`perf:budget`は再現用に残している  
`perf:budget`の使い方は[旧方式の性能予算](functional-performance-budget.md)を参照
